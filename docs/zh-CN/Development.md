# Development

**[English](../Development.md)** · 简体中文

## 角色分工

| | 我（设计 / 验收） | AI 代理（实现） |
|---|---|---|
| 玩法设计 | 提出想法、逐轮讨论并**拍板**；设计冻结前不进入实现 | 提出方案与取舍、整理成文档 |
| 规则与数值 | 决定方向与边界（如“价格 = 不可砍的基础价 + 评级加成”） | 落地为代码与数据 |
| 代码 | 审阅行为与结果 | 实现、重构、写测试 |
| 美术 | 定风格与质量门槛（“不接受平面方块拼接”） | 概念图（Codex 生图）→ Blender 脚本建模 → 导入 |
| 验收 | 亲自实机试玩，决定是否通过 | 编译、测试、截图证据 |

我不是在“把一句话丢给 AI 然后收货”：每个功能都经过设计讨论、记录决策、自动化验证和我的实机验收。

## 工作流

1. **设计先于实现。** 先在对话里把玩法讲清楚，再写进设计规格（冻结版 v0.9）和决策日志。
2. **原子任务。** 每次只做一个有验收标准的模块，以模块为单位交付，而不是零碎小修。
3. **最小充分验证。** 先跑最窄的编译/测试，再跑完整 EditMode/PlayMode。
4. **视觉证据。** UI、动画、美术改动必须有截图或逐帧图，对照概念图自查后才给我看。
5. **可恢复。** 每次会话结束更新 `PROJECT_STATE`、`WORK_LOG`、`CURRENT_TASK`，下一个会话可以直接接上。

## 我的实际贡献（示例）

- 收卡谈判系统的整体设计与三轮修订：价格结构、三种砍价招式、冤枉行家扣口碑、i 人性格、假卡的两种处理方式。
- 人格与天赋网：九种人格、交集节点数量、“代价只在人格上、天赋无代价”的原则。
- 经济与店铺布局：后仓/仓库、机器单独购买、批量送货、当铺回收废品等。
- 美术方向：深色胡桃木 + 黑金属 + 暖色 LED 的统一风格；对每个模型的质量验收。
- 反复试玩并给出修改意见（如移除常驻库存 HUD、精简界面文字）。

## 已知限制

- 以单人模式为主，多人联网尚未锁定方案。
- 部分美术仍为程序占位，计划按美术圣经逐步替换。
- 视觉与手感最终仍需要人手试玩确认。
